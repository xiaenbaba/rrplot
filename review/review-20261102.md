审查结论：走线引擎是稳的，真正会绊人的是部件 API 契约，尤其是压缩机端口和 README 快速上手。

P1

README 快速上手会报错。 d.add(parts.evaporator, ...) 引用了不存在的实例。蒸发器只能用 make_heat_exchanger(...) 生成；__init__.py 的示例是对的，README 写错了。

压缩机两套端口。 parts.compressor 是 suction / discharge / vapor_inj（示例和测试都按这套接线）。make_compressor() 却是 left / right / top / bottom，没有喷气口。按文档“改尺寸用工厂”会立刻 KeyError，EVI 回路也会丢口。

P2

add() 改几何时端口不跟着变。 四通阀、bowtie 会把 r/actuator 传给绘制，外观变了，端口仍按工厂闭包里的旧尺寸。截止阀、电磁阀、过滤器等则吞掉 kwargs，覆盖静默无效。两条路径都不会报错。

bowtie 的 in/out 与其它两口阀东西对调（东进西出），文档还写成“库内惯例”。parts.filter 覆盖了 Python 内置名。

P3

截止阀工厂注释写“贯穿阀杆”，绘制明确不贯穿。油分文档是侧进顶出，测试说明写成顶进侧出。_bowtie_valve 未知 actuator 当裸阀，其它工厂会 ValueError。style.apply_style() 在 import 时改全局 rcParams。

做得好的地方： _fit_end / _orthogonalize、Diagram.close()、端口与几何对齐（油分、U 形分离器、中间换热器抽查一致），未知 shape/style/orient 多数有明确报错。

建议先修 README，再统一压缩机端口，然后明确：add() 只许改外观，尺寸必须走工厂。

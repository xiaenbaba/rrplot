## 二、整体评价与亮点

相比历史评审（2026-10 / 2026-11），项目已演进为“Python 绘图库 + 本机零依赖 Web SVG 编辑器”的完整双轨架构，整体工程质量较高：

1. **前端零构建模块化到位**：将原单体 `app.js` 拆分为 `web/editor/` 18 个职责清晰的原生 ES 模块控制器，通过 `state` + 共享 `commands` 表解耦，无循环依赖；DOM 构造全部采用安全 API，无 XSS 风险。
2. **渲染与交互保护扎实**：[`web/canvas.js`](../web/canvas.js) 按 ID 复用 SVG 分组并采用 `DocumentFragment` 批量挂入；[`web/requests.js`](../web/requests.js) 将响应体读取纳入超时截止时间并合并排队快照；异步载入、预览、避障布线均有 revision/session 过期保护。
3. **前后端契约意识强**：共享几何夹具 [`tests/fixtures/geometry_contract.json`](../tests/fixtures/geometry_contract.json)、服务端 `RENDER_LOCK` 保护 Matplotlib 线程安全、停止接口拒绝浏览器 `Origin` 并校验随机令牌，以及 [公网部署方案](../docs/plans/public-deployment.md) 的生产改造规划都很务实。

## 三、发现的问题（按优先级）

### P1 —— 确定性功能缺陷

#### 1. 首次启动失败后，“重新连接并更新”按钮完全无效
- **位置**：[`web/editor/events.js:63-65`](../web/editor/events.js#L63-L65)、[`web/editor/ui.js:54-60`](../web/editor/ui.js#L54-L60)、[`web/index.html:93`](../web/index.html#L93)
- **原因**：`ui.js` 的 `retryService()` 专门处理了初始载入失败（`state.doc === null` 时调用 `commands.init()`），[`web/README.md:58`](../web/README.md#L58) 也承诺“首次载入失败也能用该按钮重连”。但全局点击分发写的是：
  ```js
  if (action && (state.doc || ['help', 'close-help'].includes(action)))
  ```
  白名单漏掉了 `'retry-service'`，且 `#request-retry` 没有单独绑定事件。服务未启动时打开页面，`state.doc` 为 `null`，用户启动服务后点击重连按钮不会触发任何动作。
- **测试盲区**：[`tests/test_web_recovery.py:19`](../tests/test_web_recovery.py#L19) 直接调用 `await retryService()`，未模拟按钮点击与 `state.doc === null` 场景。
- **建议**：将 `'retry-service'` 加入 `events.js:65` 允许在 `!state.doc` 时执行的动作白名单，并补一条点击重连的初始失败恢复测试。

#### 2. `export_parts_svg.py` 直接崩溃（`KeyError: 'fan_coil'`），且 `SVG/` 积压大量废弃文件
- **位置**：[`export_parts_svg.py:36-61`](../export_parts_svg.py#L36-L61)、[`rrplot/parts.py:291`](../rrplot/parts.py#L291)
- **原因**：`parts.HEX_SHAPES` 已新增 `"fan_coil"`，但 `export_parts_svg.py` 的 `HEX_CN` 仍只有 3 项，运行 `python export_parts_svg.py` 必报 `KeyError: 'fan_coil'`；同时 `COMPRESSOR_CN` 是未使用的死代码，日志仍打印“3 种换热面”。
- **伴随问题**：`SVG/` 目录入库 51 个文件，其中 30 余个为已删除图元/样式的历史残留（如 `compressor__axial.svg`、`heat_exchanger__rect_shell.svg`、`condenser.svg`、`evaporator.svg` 等）；该脚本也未被 CI `lint` 或测试覆盖。
- **建议**：补齐 `HEX_CN["fan_coil"]`、清理废弃 SVG 或改为导出前清空重建，并将 `export_parts_svg.py` 纳入 CI `ruff check`。

#### 3. 特性开关存在先有鸡还是先有蛋的死锁，且 `refresh()` 不更新能力状态
- **位置**：[`web/editor/ui.js:35-46`](../web/editor/ui.js#L35-L46)、[`web/editor/files.js:84-93`](../web/editor/files.js#L84-L93)、[`web/editor/session.js:49-71`](../web/editor/session.js#L49-L71)
- **原因**：`state.pipeMountsSupported` 与 `state.edgeLabelsSupported` 初始值均为 `false`，仅在 `replaceDocument()` 收到 `/api/resolve` 响应后赋值。但 `api()` 在**发请求之前**就拦截含 `node.mount` 或 `label.edgeId` 的图纸并报错。目前仅因默认模板 `evi_ftvi.json` 恰好不含挂接阀件与状态点才未触发；若初始载入含上述特性的图纸/模板，或用户将旧服务升级到新服务后通过 `refresh()` 重连（`refresh()` 未同步 `result.features`），前端会永久拒绝合法请求。
- **建议**：改为在 `api('resolve')` 收到响应时统一更新 `state.edgeLabelsSupported` / `state.pipeMountsSupported`，仅在已知服务端不支持（如已收到过不含该项的 `features`）时前置拦截，或由 `/api/health` / `/api/catalog` 提前声明能力。

#### 4. `_polyline_span()` 的末段兜底条件 `(a, b) is segs[-1]` 恒为 `False`
- **位置**：[`rrplot/core.py:156-165`](../rrplot/core.py#L156-L165)
- **原因**：`for (a, b), L in zip(segs, lens):` 拆包后重新构造了新元组 `(a, b)`，与 `segs[-1]` 的 `is` 身份比较恒为 `False`（已实测验证）。在 Python 3.12+（`sum()` 对浮点启用补偿求和，可能略大于循环累加的 `acc + L`）或零长折线场景下，`frac = 1.0` 会掉出循环并落入兜底分支 `return pts[-1], (1.0, 0.0), total, total, total`——导致末段朝向恒被当作向右 `(1, 0)`、箭头被静默跳过、挂接阀件角度错误。
- **建议**：改为 `for i, ((a, b), L) in enumerate(zip(segs, lens)):` 并判断 `i == len(segs) - 1`。

### P2 —— 边界缺陷、服务端健壮性与关键文档错误

#### 5. `splitRoute()` 在三通处插入重合折点，引发短管过冲与坐标编辑器校验冲突
- **位置**：[`web/geometry.js:207-217`](../web/geometry.js#L207-L217)、[`web/editor/coordinates.js:245-256`](../web/editor/coordinates.js#L245-L256)
- **原因**：`splitRoute()` 将新三通坐标 `point` 同时塞进了 `prefix` 末尾和 `suffix` 开头：
  1. **近端口过冲**：若在距设备端口 20 单位以内插入三通，非空 `vertices = [[10, 0]]` 会绕过 `route()` 的直连快路径，实测 `rrplot.scene.route` 输出 `[[0, 0], [20, 0], [10, 0]]`（管路冲过三通再折返）。
  2. **坐标编辑器冲突**：拆分后的两段管路均带有与起/终点三通重合的“幽灵折点”；用户打开“编辑折点坐标”并增删或修改任一折点时，会被 `validateCoordinateVertices` 拦截报“折点与相邻点/终点重合”。
  3. 此外 `points.indexOf(start)` 依赖数组引用相等，应由 `along()` 直接返回段索引 `index`。
- **注意**：[`tests/test_scene.py:258-275`](../tests/test_scene.py#L258-L275) 显式断言了 `prefix[-1] == point` / `suffix[0] == point`，修正时需同步更新该契约测试。

#### 6. 避障布线的两处边界缺陷（网格浮点容差 & 过度冲突拦截）
- **位置**：[`web/routing.js:102-117`](../web/routing.js#L102-L117)、[`web/routing.js:200-208`](../web/routing.js#L200-L208)
- **问题 1（网格边界 `EPS` 不一致）**：`inPage` 允许 `limits[0] - EPS <= p <= limits[2] + EPS`，但构建坐标压缩数组 `xs` / `ys` 时用的是严格过滤 `x >= limits[0] && x <= limits[2]`。当浮点旋转或偏移使 `start` / `target` 落在 `-1e-10` 或 `page.width + 1e-10` 时，`inPage` 放行而 `xs` 将其滤除，`xs.indexOf(...)` 返回 `-1`，导致 `startId` / `targetId` 错位或产生 `NaN`。建议先将边界内容差坐标夹紧（clamp）到 `[limits[0], limits[2]]`。
- **问题 2（`validateRoutedMounts` 误拦无关冲突）**：第 200–208 行遍历全部 `candidate.edges` 与全部 `valves`，未限制 `byId.has(valve.mount.edgeId) || byId.has(edge.id)`（对比第 188 行仅检查变动管路上的阀件）。若图纸上原本存在某条无关管路靠近某个无关挂接阀，用户单独选中另一条管路执行避障布线时会被整批误拒。

#### 7. 文档中的“自备字体注册方法”实际失效
- **位置**：[`rrplot/style.py:14-17`](../rrplot/style.py#L14-L17)、[`rrplot/_primitives.py:3-12`](../rrplot/_primitives.py#L3-L12)、[`README.md:221-222`](../README.md#L221-L222)、[`docs/tutorial.rst:339-340`](../docs/tutorial.rst#L339-L340)
- **原因**：`README.md` 与 `docs/tutorial.rst` 指导用户调用 `fontManager.addfont()` 后把字体名插入 `rrplot.style.FONT_CANDIDATES` 头部。但 `FONT`、`_installed`、`FONT_STACK` 均在 `import rrplot` 时一次性冻结，且 `_primitives.txt()` 与 `core.Pipe._draw_state()` 直接按值引用了模块导入时的 `FONT_STACK`，后续修改 `FONT_CANDIDATES` 既不影响出图也不影响 `use_font()` 输出。
- **补充**：[`rrplot/style.py:49`](../rrplot/style.py#L49) 在 `import` 时仍无条件调用 `apply_style()` 修改全局 `matplotlib.rcParams`，虽保留兼容但仍会影响同进程中用户的其他 Matplotlib 绘图；建议增加 `register_font()` / `refresh_fonts()` 辅助函数并修正文档。

#### 8. 场景校验、性能重复计算与本机服务健壮性
- **布尔值绕过旋转角校验**：[`rrplot/scene.py:90`](../rrplot/scene.py#L90) `angle not in (0, 90, 180, 270)` 未排除 `bool`，`{"rotation": false}` 会被合法接受（因 `False == 0`）。
- **非法 JSON 类型直接抛 `TypeError`**：[`rrplot/scene.py:105-111`](../rrplot/scene.py#L105-L111) 与 [`164`](../rrplot/scene.py#L164) 未先校验 `nodeId`/`portId`/`junctionId` 为字符串，传入列表/字典时 `validate_scene()` 直接抛 `TypeError: unhashable type` 而非文档约定的 `ValueError`。
- **单次解析重复计算**：[`rrplot/scene.py:83-84`](../rrplot/scene.py#L83-L84) 与 [`234`](../rrplot/scene.py#L234) 中，`validate_scene()` 已对每个节点算过一次 `describe()`（含挂载时的 `route()`），`resolve_scene()` 又立刻重算一遍；叠加 `describe()` 内调用 `make_registered()` 再次调用 `normalize_params()`，单次 `/api/resolve` 对每个节点执行 **5 次** `normalize_params()` 和 **2 次**部件构造。公网部署前值得合并清理。
- **HTTP 服务错误处理与并发细节**：
  - [`server/run.py:82-106`](../server/run.py#L82-L106)：`do_GET` 未对路径片段做 `urllib.parse.unquote`，且缺少类似 `do_POST` 的 `except Exception:` JSON 500 兜底；`do_POST` 第 148–152 行未单独处理客户端断连/超时（`OSError`），会往已断连接写 500 并打出多余 traceback。
  - [`server/service.py:29-49`](../server/service.py#L29-L49)：`code_fingerprint()` 在 `ThreadingHTTPServer` 下无锁读写全局 `_cached`，每次 `/api/health` 都遍历 `rrplot`/`server`/`web` 全部文件；若某临时文件在 `rglob` 与 `stat()` 间被删，`/api/health` 直接返回 400。
  - [`server/service.py:67-77`](../server/service.py#L67-L77)：`save_instance()` 写入含 `shutdown_token` 的状态文件使用默认 umask，POSIX 多用户环境下其他本机用户可读（建议设为 `0o600`）。
  - [`web-service.cmd:4-9`](../web-service.cmd#L4-L9)：硬编码检测 `.venv\Scripts\python.exe`，若用户使用 `venv/`、conda 或系统 Python 则无法使用 `.cmd` 启停脚本。

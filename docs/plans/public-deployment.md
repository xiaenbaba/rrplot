# rrplot 公网部署方案

状态：待实施。基线：`9613bed`。本文定义首期部署范围、交付文件、上线门槛和回退流程。

## 目标与范围

首期采用 **Linux 单机、独立 HTTPS 域名、受控试运行**。受邀用户可加载模板、编辑、导入与下载 JSON、预览及导出 SVG、PNG、PDF。沿用现有 JSON 格式，草稿仍保存在访问者的浏览器。首期不引入数据库、云端图纸库、多人协作或公开匿名访问；开放匿名访问需单独评估容量和滥用防护。

本机草稿绑定浏览器和站点来源。用户从 `localhost` 切换到公网域名时，需在旧页面导出 JSON，再在新站点导入。解析和导出会把图纸提交到服务器处理；部署方需告知访问者这一点，并避免保存请求正文、图纸和导出内容。

## 部署架构

```text
访问者浏览器
  ↓ HTTPS，独立域名的根路径
Nginx：证书、访问控制、请求限制、静态文件
  ↓ 同源 /api/，仅明确允许的路由，内部回环
Gunicorn：生产 WSGI 服务，交给 systemd 托管
  ↓
rrplot 场景解析、图元绘制、Matplotlib Agg 导出
```

现有前端使用 `/api/` 和根路径静态资源。首期直接使用独立域名根路径，避免子目录部署改造；HTTPS 同时满足浏览器对 `crypto.randomUUID()` 的要求。Nginx 向外监听 443，80 仅用于跳转和需要时的证书验证。后端监听 `127.0.0.1`，防火墙不开放后端端口。

[当前服务](../../server/run.py)基于 `http.server`，包含本机停止令牌、服务指纹和实例管理。正式部署新增独立 WSGI 入口，复用图元目录、模板、解析与导出逻辑，保留本机启动方式。可用 Flask 实现生产入口以减少手写请求处理；Flask、Gunicorn 和锁定依赖只安装到公网部署环境。

## 上线前改造

| 项目 | 首期要求 |
| --- | --- |
| 接口 | 允许 `GET /api/catalog`、`/api/templates`、`/api/templates/{id}`、`/api/glyph/{type}`，以及 `POST /api/resolve`、`/api/preview`、`/api/export/{svg,png,pdf}`。`GET /api/health` 只提供浏览器兼容所需的公开状态。生产应用不注册 `/api/shutdown`，代理也不转发它或其它未知 API。 |
| 前端服务状态 | 部署模式去掉 Windows 启停提示、PID 与本机指纹展示；健康接口与页面一起改造，避免生产版本被判为旧版。健康探针仅检查轻量状态，不逐次扫描代码或渲染图纸。 |
| 访问控制 | 受控试运行可使用 HTTPS 下的反向代理认证或既有身份网关；保护页面、静态资源与 API。使用站点来源校验拦截跨站写请求，不开放宽泛 CORS；代理认证独立于图纸数据存储。 |
| 请求限制 | 代理和应用明确使用现有 `5,000,000` 字节 JSON 上限，保留页面、图元数、折点、DPI 和 PNG 像素限制；超限返回可识别错误。入口按客户端及路由设置请求速率与连接上限，导出单独限制。 |
| 渲染资源 | Matplotlib 使用 Agg。先用少量独立 worker 进程，每个进程串行渲染、避免线程共享绘图状态；限制并发与等待，过载返回 `429` 或 `503`。设置 worker 回收和进程内存限制；通过压测确定配置，避免仅增加线程让请求排在渲染锁后。 |
| 超时 | 保留现有普通请求约 20 秒、预览/导出约 60 秒的前端截止时间作为基线。压测后协调代理和应用预算，给排队、渲染、传输留时间；浏览器断开连接不作为服务器停止计算的保障。 |
| 数据与日志 | 应用使用专用非特权账号，版本目录只读，`MPLCONFIGDIR` 指向单独的可写缓存目录。JSON 和导出按请求处理，不建立服务器图纸库。日志只保留时间、状态码、耗时、路由模板和必要诊断，去除图纸正文、认证头和令牌。 |
| 字体 | Linux 安装 Noto Serif CJK SC 等受支持的中文字体，启动时准备字体缓存；用含中英文、设备标注和下标的图纸核对三种导出格式。 |

初始环境可从 **2 vCPU、4 GB 内存**开始做容量验证。该配置是试运行测量起点，不代表并发承诺。根据模板、真实大图和 PNG 导出的峰值内存调整 worker 数量及实例规格。

## 实施顺序与验收

| 阶段 | 工作 | 通过条件 |
| --- | --- | --- |
| 1. 生产入口 | 复用现有绘图逻辑，加入 WSGI 入口和生产依赖，保留本机入口 | 本机编辑器回归通过；生产入口通过目录、模板、解析、预览和两种矢量及 PNG 导出的契约测试；没有停止服务路由 |
| 2. 发布包与测试环境 | 按 Git 提交或标签构建发布包，生成代理与 systemd 配置，在测试域名部署 | HTTPS 生效；未授权用户无法访问编辑器及 API；后端端口外部不可达；发布包只含部署清单文件 |
| 3. 浏览器与资源验收 | 加载默认及 VRF 模板，测试放置、连线、避障、草稿恢复、JSON 保存再导入、三种导出；覆盖超限、过载、超时和失败后重试 | 分享的测试图可正常往返；中文与连接位置正确；受限请求有明确反馈，图纸及撤销记录仍可访问 |
| 4. 容量与回退演练 | 测量 50/200/500 节点样本和真实大图，记录解析/预览/导出耗时、峰值 RSS、失败率与队列长度 | 在约定试运行人数下不出现持续资源耗尽；常用图纸操作落在客户端截止时间内；能切回上一版并恢复功能 |
| 5. 公网试运行 | 设定域名与证书、受邀人员和告警负责人，开放访问并观察 | 先完成以上各项，再开放受控公网访问；匿名开放另立验收 |

## 发布和回退

1. 每次发布使用明确提交或标签生成制品，将应用和该版本的依赖放入 `/opt/rrplot/releases/<版本>/`；服务器密钥和配置保存在 `/etc/rrplot/`。
2. 发布前保留上一版制品和配置，核验代理配置并在测试环境走完核心操作。生产切换后确认 HTTPS、健康检查、模板和导出。页面与静态资源来自同一个版本；首期对 HTML/JS 使用重验证，启用长期缓存前先实现带版本的资源 URL。
3. 通过 `current` 链接切换版本并重启服务。若健康检查或关键操作失败、出现持续超时或内存异常，切回上一版（含该版依赖和必要配置），重启并复验。首期没有数据库迁移；保持同一 HTTPS 域名，用户草稿仍由浏览器保存。

实施前需确定真实域名、Linux 主机、访问认证方式和试运行人数。开发与验收可先使用本机和隔离测试环境开展，无需提前开放生产端口。
